\paragraph{Decision-trace analysis.}
The scheduler trace contains 31 agent updates between global steps 1 and 1902.
Each update stores the signed residual vector, the compact task statistics, and a natural-language rationale.
The run starts with a conservative residual budget of $\pm 0.15$ and switches at meta-training step 400 to a wider budget of $\pm 0.5$.
This makes the early scheduler behavior cautious, while giving the agent enough authority later to suppress attacks that appear saturated or unproductive.
The rationales show that the agent does not behave as a simple hard-task miner.
Instead, it repeatedly weighs four kinds of evidence: attack difficulty from recent query loss, uncertainty from loss volatility, coverage from usage and recency, and usefulness from recent reward or loss improvement.
Across the trace, the rationales frequently cite over-sampling and under-sampling, high or low loss, uncertainty, reward, recency, and balance.
This makes the scheduler auditable: the heatmap gives the action, while the rationale explains why the action was chosen.

The most visible pattern is the \texttt{crop} row.
During the middle of training, the agent often increases \texttt{crop} because its recent loss and uncertainty remain high.
Later, when \texttt{crop} has saturated usage but poor progress, the rationale switches from ``hard and informative'' to ``over-sampled'' and the residual becomes strongly negative.
This sign reversal is important: the agent is not merely increasing all high-loss tasks; after the residual budget is widened, it can also decide that a hard task should receive less sampling when the trace suggests diminishing returns.
The \texttt{msg\_app} task is typically increased in the early and middle phases because the rationales identify persistent loss and uncertainty under compound platform-style processing.
By contrast, \texttt{occlusion} is often reduced early when it has low loss and low uncertainty, but receives positive residuals later to maintain coverage and stabilize under-sampled regions of the task pool.
Tasks such as \texttt{downup50}, \texttt{jpeg}, and \texttt{clean} usually receive smaller corrections because the agent treats them as stable, improving, or useful mainly for coverage.

\subsection{Benchmark Design}

The final evaluation is organized around two complementary questions.
First, does episodic verifier training improve SpiderMark robustness over a non-meta verifier?
Second, under matched verifier architecture, attack pool, support/query sizes, and 2000-step training budget, does the agentic AI scheduler outperform non-agentic task schedulers?
Uniform sampling serves as a minimal anchor, while cyclic scheduling is kept as an optional diagnostic rather than a main compute target.
The scheduler benchmark compares the proposed agentic scheduler against non-contextual UCB bandits~\cite{auer2002finite}, ATS-style adaptive task scheduling~\cite{yao2021ats}, BASS-style contextual bandits~\cite{ban2023bass}, and Adaptive Sampler-style task sampling~\cite{wang2024tasksampler}.
A GCP-style task-weighting proxy~\cite{liu2020adaptive} is included as an appendix candidate because its original class-combination setting does not map exactly to our attack-task pool.
DERTS remains an important future baseline, but a faithful implementation requires full task-pool gradient subset optimization rather than the scalar online feedback currently available in the training loop.
All rows in the main scheduler table use the same 2000-step budget; the table therefore reports only downstream accuracy.

\paragraph{Scheduler benchmark setup.}
All scheduler rows use the same SpiderMark verifier architecture, optimizer settings, first-order meta-learning update, and attack-task interface.
The training task pool contains seven attack conditions: clean images, down-up resampling, crop, JPEG compression, blur, message-app processing, and occlusion.
Each meta-training step samples one attack task, constructs an attack-conditioned support/query episode with $n_s=16$ support examples and $n_q=16$ query examples, performs the support adaptation, and updates the verifier using query loss.
Unless otherwise stated, each scheduler is trained for 2000 meta-training steps with the same checkpointing rule and evaluated only after all selected scheduler checkpoints are complete.

For the proposed row, the agentic scheduler receives the compact JSON state described in Sec.~\ref{sec:method} every 100 meta-training steps.
The agent outputs residual task corrections rather than absolute sampling probabilities.
The local controller clips each correction to the configured residual range, enforces a minimum task probability, normalizes the distribution, and logs the final task weights, rationale, latency, and any fallback event.
This ensures that the comparison tests agentic task selection while keeping the verifier update, attack pool, and compute budget fixed.

\paragraph{Evaluation protocol.}
Every trained scheduler checkpoint is evaluated with the same downstream attack suite used in the current checkpoint sweep: clean, strong JPEG, message-app compound processing, down-up resampling, blur, random crop, occlusion, geometric warp, and the mixed training augmentation.
The main scheduler table reports per-attack accuracy and mean accuracy.
We additionally retain AUROC, threshold statistics, scheduler traces, and runtime overhead in the benchmark artifacts so that the final paper can report stability and operating-threshold behavior when all rows are complete.

\subsection{Planned Metrics}

We will report accuracy at a fixed operating threshold, AUROC, and where possible threshold stability across attacks.
Because watermark verification is often deployed at a single threshold, accuracy under a fixed policy is important even when AUROC is high.
For image quality and semantic preservation, the benchmark should reuse the SpiderMark metrics: FID and CLIP image-text similarity.
Because the watermark injection mechanism is unchanged, these quality metrics are supporting evidence rather than the main comparison axis.
For agentic scheduling itself, we should additionally report training cost, agent-call overhead, checkpoint sensitivity, task sampling distribution, and performance variance across random seeds.

\subsection{Experiment Roadmap}

The current table is promising but not yet sufficient for a CVPR submission.
We organize the remaining experiments around a scheduler benchmark plus a SOTA/canonical meta-learning context table.
The repository-level execution plan is maintained in \texttt{BENCHMARK\_PLAN.md}; here we summarize the benchmark structure expected in the final paper.

\paragraph{Stage 1: anchor baselines.}
This stage establishes the fixed reference points: the improved non-meta SpiderMark verifier and the currently available meta-trained verifier checkpoints.
It answers whether the direction is worth expanding and provides the non-meta anchor for all later scheduler deltas.

\paragraph{Stage 2: scheduler benchmark.}
This stage trains and evaluates the fixed comparison set in Table~\ref{tab:scheduler_benchmark_skeleton}, with the agentic AI scheduler as the proposed method.
The current execution plan is training-first: finish all selected scheduler checkpoints, then run the same downstream evaluation suite for every row.
This avoids mixing preliminary eval settings with final matched-compute results.

\paragraph{Stage 3: SOTA/canonical meta-learning comparison.}
After the scheduler comparison is stable, this stage fixes the scheduler and compares FOMAML, MAML, ANIL, Reptile, Matching Networks-style attention, Prototypical Networks-style prototypes, and an R2D2-style differentiable ridge solver head under the same attack pool, number of meta-training steps, support/query sizes, and checkpoint-selection rule.
This separates improvements from the meta-learning update itself from improvements caused by agentic task scheduling.

\paragraph{Stage 4: stability and ablations.}
This stage checks that the scheduler ranking is stable rather than a single-run artifact.
It should include seed variance, checkpoint selection, held-out attacks or held-out prompts, scheduler overhead, and quality metrics for the final selected configuration.
External watermarking baselines can be included as contextual comparisons, but they are not the main benchmark required to support the paper's claim.

The concrete missing items are:
\begin{itemize}
    \item repeat the meta versus no-meta comparison across multiple seeds;
    \item finish the seed-0 scheduler benchmark for UCB, ATS-style, BASS-style, Adaptive Sampler-style, and agentic task sampling;
    \item optionally evaluate the GCP-style proxy as an appendix scheduler row;
    \item evaluate FOMAML, MAML, ANIL, Reptile, Matching Networks-style, Prototypical Networks-style, and R2D2-style ridge baselines under the selected fixed scheduler and compute budget;
    \item compare checkpoint-selection strategies across the full downstream sweep;
    \item test transfer to an unseen prompt or dataset split, ideally COCO as in the SpiderMark paper;
    \item measure agent-call overhead, scheduler overhead, image quality, and semantic preservation for the final selected method.
\end{itemize}
